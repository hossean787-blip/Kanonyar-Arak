# کانون‌ها | اپ مستقل دانشجویی

**نسخه آزمایشی:** `0.5.0-live-backend-beta` — اندروید ۸ به بالا (API 26+).

این مخزن کاملاً مستقل است؛ هیچ داده، سرور یا فایل اجرایی از اپ‌های دیگر به این برنامه منتقل نمی‌شود.

## پنج صفحه
خانه، کانون‌ها، رویدادها، فعالیت‌های من، حساب کاربری.

## اتصال عملیاتی
برنامه با `WebViewAssetLoader` (مبدأ HTTPS داخلی امن) اجرا می‌شود و صرفاً به پایگاه داده اختصاصی **Kanonha** متصل است:

- پروژه: `cnqcysnjinghzzrzanpj` — <https://supabase.com/dashboard/project/cnqcysnjinghzzrzanpj>
- منطقه: `eu-west-1`
- تنظیمات عمومی موبایل: `app/src/main/assets/config.js`؛ فقط کلید **publishable** داخل APK قرار می‌گیرد.
- `Content-Security-Policy` فقط همین آدرس Supabase را برای ارتباطات API مجاز می‌کند.
- پنج جدول اصلی + RLS فعال؛ کلید خصوصی دیتابیس داخل اپ وجود ندارد.
- ورود/ثبت‌نام با ایمیل و رمز عبور و تأیید ایمیل طبق تنظیم Supabase؛ پروفایل خوداظهاری، درخواست عضویت با وضعیت pending، ثبت‌نام آنلاین رویدادهای منتشرشده با کنترل ظرفیت.
- در حال حاضر **۰ کانون و ۰ رویداد واقعی وارد شده‌اند**؛ تا زمان درج داده از سمت مسئول مجاز، فهرست‌ها خالی خواهند بود. نام‌سازی ساختگی ممنوع است.

## آزمون‌ها
```bash
node tests/ui-smoke.cjs
node tests/backend-smoke.cjs
node tests/online-ui-smoke.cjs
node tests/live-api-smoke.cjs
gradle :app:assembleDebug --no-daemon
```
GitHub Actions مراحل فوق را (با JDK 17، Android SDK 35 و Gradle 8.9) اجرا کرده و APK **Debug** منتشر می‌کند.

- `live-api-smoke.cjs`: خواندن واقعی کانون/رویدادهای عمومی و اطمینان از رد دسترسی ناشناس به جدول‌های خصوصی؛ بدون ساخت کاربر یا تغییر داده.
- آزمون دستی پایگاه داده: بازگردانی تراکنش (ROLLBACK) برای نقش‌های دانشجویان آزمایشی، کنترل RLS، عدم امکان جعل university_verified و رزرو اتمی ظرفیت. فایل گزارش در `supabase/SETUP_FA.md`.

## محدودیت‌های نسخه بتا
این نسخه **تجاری یا آماده استفاده گسترده دانشجویان نیست**؛ قبل از انتشار عمومی، موارد زیر لازم است: ثبت اطلاعات حقیقی کانون‌ها و رویدادها توسط مسئول مجاز، بررسی تنظیمات ارسال ایمیل و محدودیت نرخ، تأیید شماره دانشجویی از منبع معتبر، آزمون دو حساب واقعی و تست نصب روی گوشی. هنوز پنل تأیید مدیر، QR قابل اعتبارسنجی، پرداخت و بلیت معتبر پیاده‌سازی نشده‌اند.

داده نمایشی نسخه‌های پیشین با حساب آنلاین مخلوط نمی‌شود. تغییرات نسخه آزمایشی مستقیم به داده پروژه‌های دیگر دسترسی ندارند.
