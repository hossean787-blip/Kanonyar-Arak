## موارد انجام‌شده و شواهد
۱. **دیتابیس FCM:** migration `kanonha_push_fcm_v0931` در پروژه اختصاصی `cnqcysnjinghzzrzanpj` اعمال شده؛ جدول `kanonha_push_devices` دارای RLS و ۴ سیاست دسترسی بر پایه `auth.uid()` و بدون حق SELECT برای `anon` است. آزمون واقعی سه شناسه موقت، جداسازی SELECT/UPDATE/DELETE و رد ثبت دستگاه به نام حساب دیگر را تأیید کرد. آزمون در تراکنش `ROLLBACK` بود و پس از آن ۱ حساب حقیقی و ۰ دستگاه پوش باقی ماند.
۲. **فرستنده سرور:** Edge Function `kanonha-fcm-delivery` نسخه ۲ با `verify_jwt=false` و بررسی اجباری کلید محرمانه سرور در هدر `apikey` مستقر و وضعیت `ACTIVE` است. فرستنده payload اعلان را از پایگاه داده مجدداً می‌خواند، bearer سمت سرور را می‌سنجد، و فقط با وجود Firebase secret پیام می‌فرستد. **هنوز هیچ تحویل پوش واقعی اثبات نشده**.
۳. **اندروید:** Firebase Messaging در نسخه ۰.۹.۳۱ اضافه شده است؛ تنظیمات عمومی Firebase از متغیرهای مخصوص ساخت وارد می‌شوند و کلید خصوصی داخل APK وجود ندارد. توکن دستگاه در جلسهٔ کاربر واردشده ثبت و هنگام خروج از فهرست سرور حذف می‌شود. نمایش اعلان برای حساب دیگری در همین دستگاه مسدود است.
۴. **آزمون‌های منبع:** `tests/push-fcm-smoke.cjs` قرارداد RLS، webhook، Android service و عدم وجود credential خصوصی را بررسی می‌کند. مسیرهای قبلی عضویت، نظرسنجی، رویداد، گواهی و بیومتریک نیز باید در CI موفق باشند.
۵. **کنترل سلامت:** Supabase health advisor بدون یافته؛ Security Advisor دارای دو خانواده هشدار است (۱۱ مورد SECURITY DEFINER قابل‌فراخوانی برای authenticated و محافظت گذرواژه‌های افشاشده خاموش). SECURITY DEFINERها مستلزم بازبینی موردی هستند؛ در دو تابع اصلی check-in/issue-certificate کنترل کاربر، نقش و مالکیت بررسی شد، اما اعلام «امنیت کامل» مجاز نیست.

## الزامات عملیاتی باقی‌مانده
- Firebase Project اختصاصی برنامه، Android App با package `ir.kanonha.app` و فعال‌کردن Firebase Cloud Messaging؛ بدون Firebase واقعی، `AndroidPush.supported()` مقدار false می‌دهد. تنظیمات **عمومی** ساخت (در GitHub Actions Secrets):
  - `KANONHA_FCM_PROJECT_ID` — شناسه پروژه Firebase
  - `KANONHA_FCM_APP_ID` — Android App ID
  - `KANONHA_FCM_API_KEY` — کلید عمومی Firebase API
  - `KANONHA_FCM_SENDER_ID` — Project Number/Sender ID
- **محرمانه فقط روی سرور:** JSON حساب خدمت Firebase در Supabase Edge Functions Secrets با نام `KANONHA_FIREBASE_SERVICE_ACCOUNT_JSON`. JSON حساب خدمت، private key یا password را در GitHub، چت یا APK وارد نکنید.
- تریگر وب‌هوک `kanonha_fcm_delivery_webhook` روی درج `public.kanonha_notification_deliveries` با `pg_net` و تابع خصوصی `kanonha_private.enqueue_fcm_notification()` نصب و در تراکنش بازگشتی آزموده شد. کلید `kanonha_fcm_sender_apikey` باید توسط مالک در Supabase Vault ثبت شود؛ تا آن زمان تریگر عمداً هیچ درخواست ارسالی ایجاد نمی‌کند. **تا اتصال Firebase و ثبت کلیدهای واقعی، اعلان‌های بسته‌بودن اپ کار نمی‌کنند.**
- آزمون دستگاه Android 8 تا 16: نصب افزایشی امضاشده روی نسخه قبلی، حفظ داده محلی، ورود با دو کاربر واقعی، ثبت/تعویض توکن، اعلان در foreground/background/بسته‌بودن اپ، مجوز Android 13+، عدم نمایش اعلان حساب قبلی پس از خروج، آزمایش اثرانگشت و قطع شبکه.
- آزمون واقعی سه‌نقشی با حساب‌ها و کانون/رویدادهای مجاز: درخواست و تأیید عضویت، انتشار رویداد توسط دبیر، ثبت‌نام، بلیت QR، بررسی کنترل ورود زودهنگام، ثبت حضور، صدور PDF و استعلام QR. فایل `tests/live-three-role-e2e-v0931.sql` برای تراکنش بازگشتی آماده شده اما **اجرای نسخه اصلاح‌شدهٔ آن توسط محدودیت ابزار مسدود و هنوز آزموده نشده**. دو اجرای پیشین به‌ترتیب به‌درستی‌سنجی دانشگاه و column-level permissions برخورد کردند؛ داده دائمی تولید نکردند.
- بررسی تنظیم `Leaked Password Protection` در Supabase Auth و ممیزی ۱۱ RPC دارای `SECURITY DEFINER` پیش از عرضه گسترده.

### تکمیل و آزموده‌شده
- **آزمون شبیه‌ساز:** GitHub Actions [اجرای 43365996282](https://github.com/hossean787-blip/Kanonyar-Arak/actions/runs/43365996282) در API 33 (اندروید ۱۳) و API 35 (اندروید ۱۵) موفق شد؛ نصب Debug، اجرای MainActivity، بازگشت به خانه و اجرای مجدد، و نبود خطای `AndroidRuntime` مربوط به بسته در دو شبیه‌ساز کنترل شد. دو بسته شواهد حاوی screenshot/log با اندازه‌های تقریبی ۰٫۸ و ۱٫۱ مگابایت وجود دارند. این آزمون روی شبیه‌ساز است، نه روی تلفن فیزیکی.
- **ساخت امضاشده:** جریان [43366116507](https://github.com/hossean787-blip/Kanonyar-Arak/actions/runs/43366116507) موفق شد؛ CI کامل [43366116490](https://github.com/hossean787-blip/Kanonyar-Arak/actions/runs/43366116490) نیز موفق شد.
- **دسترسی پایگاه داده:** ۲۳ از ۲۳ جدول عمومی `kanonha_*` دارای RLS؛ از ۱۶ تابع SECURITY DEFINER هیچ‌کدام برای `anon` قابل اجرا نیستند؛ هر ۱۱ تابع قابل اجرا برای `authenticated` به `auth.uid()` ارجاع می‌دهند و `search_path` همهٔ ۱۶ تابع قفل شده است. آزمون SQL با نقش بدون مجوز، نشت سوابق عضویت/رویداد و ساخت/کپی نظرسنجی را رد کرد.
- **FCM server:** سرویس `kanonha-fcm-delivery` نسخه ۲ با کنترل کلید server-side و پشتیبانی `SUPABASE_SECRET_KEYS` مستقر شد. میزبانی `verify_jwt=false` برای webhook است؛ صرفاً کلید محرمانهٔ صحیح API پذیرفته می‌شود و کلید عمومی کافی نیست.
- **وب‌هوک:** مهاجرت `kanonha_push_webhook_v0932` افزونه `pg_net`، تریگر درج اعلان و تابع امن `kanonha_private.enqueue_fcm_notification()` را نصب کرد. نه `anon` و نه `authenticated` مجوز اجرای مستقیم تابع خصوصی را ندارند. درج کمپین/اعلان در SQL تراکنشی و `ROLLBACK` موفق شد و تعداد اعلان‌ها و کمپین‌های واقعی پس از آزمون صفر باقی ماند.
- **نداشتن اعتبارنامه:** استعلام وضعیت (فقط وجود نام، نه مقدار) نشان داد نام کلید `kanonha_fcm_sender_apikey` در Vault ثبت نیست. بنابراین وب‌هوک عمداً غیرفعال عملیاتی می‌ماند.

### متوقف به‌دلیل مانع
- افزونه رسمی Firebase برای حساب ChatGPT **متصل/نصب نیست** و هیچ Firebase Project/کلید مورد تأیید برای این اپ در دسترس نیست. اتصال حساب و ثبت Secrets نیازمند اقدام کاربر و دسترسی صاحب پروژه است؛ قرار دادن service-account/private key در APK یا مخزن ممنوع است.
- امکان آزمون روی گوشی حقیقی و با چند حساب واقعی در ابزارهای همین نشست وجود ندارد. در دیتابیس عملیاتی یک حساب و صفر رویداد وجود دارد، پس تأیید ثبت‌نام تا استعلام گواهی واقعی انجام نشده است.
- Supabase Security Advisor همچنان هشدارهای ۱۱ تابع SECURITY DEFINER (با مجوز عمدی و کنترل درون تابع) و خاموش بودن Leaked Password Protection را نشان می‌دهد. گزینهٔ دوم طبق مستندات Supabase **فقط در Pro به بالا** ارائه می‌شود؛ بدون رضایت برای هزینه نباید سرویس را ارتقا داد.
- آزمون کامل ارسال پوش از یک کمپین واقعی تا دستگاه واقعی، اثرانگشت/چهره، PDF چاپی، انقضای بلیت و ارتقای APK نصب‌شدهٔ واقعی همچنان شرط انتشار تجاری هستند.
