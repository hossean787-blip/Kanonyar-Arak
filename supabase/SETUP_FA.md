# راه‌اندازی نسخه آنلاین کانون‌ها — v0.4.0

## وضعیت و استقلال
نسخه ۰.۴.۰ امکان اتصال به یک پروژه Supabase **جدید و اختصاصی کانون‌ها** را دارد.
پایگاه دادهٔ متصل دیگر (`saba-auth`) متعلق به این پروژه نیست و نباید در آن تغییر ایجاد شود.
تا زمانی که تنظیمات این پروژه اختصاصی وارد نشوند، برنامه مانند نسخه ۰.۳.۳ فقط داده‌های **نمایشی آفلاین** را نشان می‌دهد و هیچ ثبت‌نامی در سرور انجام نمی‌شود.

## مراحل فعال‌سازی (بدون سرویس مشترک)
۱. در حساب Supabase یک **پروژه مستقل با نام Kanonha** بسازید و منطقه استقرار، سازمان و هزینهٔ احتمالی را پیش از ایجاد تأیید کنید.
۲. در SQL Editor فقط همان پروژه جدید، فایل `supabase/schema-v040.sql` را اجرا کنید. طرح شامل پنج جدول با RLS، مالکیت کاربر و قفل اتمی ظرفیت است.
۳. با دستورهای خواندنی SQL یا بخش Advisors در Supabase، وضعیت RLS و مجوزها را تأیید کنید.
۴. Authentication > Providers > Email: ورود ایمیل/رمز و تأیید ایمیل را فعال نگه دارید. برای استفاده گسترده، تنظیم ارائه‌دهنده ایمیل با دامنه معتبر ضروری است.
۵. فایل `app/src/main/assets/config.js` را برای ساخت مخصوص همین پروژه با URL و **publishable key** پر کنید. مثال:

```js
window.KANONHA_CONFIG = Object.freeze({
  url: 'https://YOUR_KANONHA_PROJECT.supabase.co',
  publishableKey: 'sb_publishable_YOUR_PUBLIC_KEY'
});
```

**هرگز secret key، service_role یا رمز پایگاه داده را در اپ، مخزن یا Android resources قرار ندهید.** کلید Publishable برای انتشار کلاینت است؛ امنیت داده باید به RLS متکی باشد.
۶. با دسترسی مدیر به همان پروژه، کانون‌ها و رویدادهای واقعی را درج کنید. رکورد کانون جدید به‌طور پیش‌فرض `is_active=false` است و رویداد جدید با `is_published=false` مخفی می‌ماند. تاریخ رویداد باید در آینده باشد، مهلت ثبت‌نام جلوتر از لحظه فعلی و قبل از شروع رویداد، و ظرفیت عدد مثبت باشد. **این فایل عمداً دادهٔ واقعی یا نمونه را در پایگاه داده وارد نمی‌کند.**
۷. آزمون عملی روی گوشی با دو حساب واقعی: ایجاد حساب، تأیید ایمیل، ورود، ذخیره پروفایل، درخواست عضویت، ثبت‌نام رویداد، جلوگیری از تکرار، رد دسترسی به داده دانشجوی دیگر، سقف ظرفیت و خروج.

## مدل مجوز
- `kanonha_profiles`: فقط خود کاربر اجازه مشاهده و ویرایش نام/شماره دارد؛ مقدار `university_verified` برای کاربر قابل ویرایش نیست.
- `kanonha_clubs`: کانون‌های فعال برای همه قابل مشاهده‌اند؛ ساخت/ویرایش از اپ دانشجو ممکن نیست.
- `kanonha_events`: رویدادهای منتشرشده خواندنی هستند؛ ظرفیت و زمان پایان ثبت‌نام در سرور کنترل می‌شود.
- `kanonha_memberships`: درخواست عضویت از نوع `pending`، فقط برای حساب درخواست‌دهنده قابل مشاهده است. تأیید مدیریت در نسخه بعدی خواهد آمد.
- `kanonha_registrations`: ثبت‌نام قطعی رویداد رایگان با قفل ظرفیت دیتابیس انجام می‌شود؛ هر کاربر فقط رکورد خود را می‌بیند؛ تکرار با یکتایی ترکیبی جلوگیری می‌شود.

## محدودیت‌ها
- **شماره دانشجویی خوداظهاری است، نه تأیید دانشگاهی.** هیچ اتصالی به سامانه دانشگاه یا پیامک احراز هویت وجود ندارد. از عنوان «تأیید دانشجو» استفاده نشود.
- امکان ساخت حساب با ایمیل و رمز وجود دارد؛ نشست صرفاً در حافظه موقت برنامه باقی می‌ماند و با بسته‌شدن کامل برنامه نیاز به ورود مجدد است.
- در نسخه آنلاین «بلیت QR معتبر»، پرداخت، پنل تأیید عضویت، صدور گواهی و تأیید هویت دانشگاه وجود ندارند.
- API پیش‌نمایش فقط پس از راه‌اندازی واقعی پروژه مستقل و آزمایش امنیت و ظرفیت برای استفاده با اطلاعات حقیقی مناسب است.
- **ترک رویداد/حذف ثبت‌نام از سوی دانشجو فعلاً وجود ندارد** تا شمارنده ظرفیت به‌اشتباه کاهش پیدا نکند.

## آزمون‌های قابل تکرار
```sh
node --check app/src/main/assets/app.js
node --check app/src/main/assets/backend.js
node tests/ui-smoke.cjs
node tests/backend-smoke.cjs
node tests/online-ui-smoke.cjs
gradle :app:assembleDebug --no-daemon
```

این آزمون‌ها از سرور واقعی استفاده نمی‌کنند و فقط رفتار کلاینت/قرارداد API را با شبیه‌ساز بررسی می‌کنند. آزمون انتهابه‌انتها و Advisors فقط بعد از ساخت پروژه جدید قابل اجراست.

## اصلاحات امنیتی ۰.۴.۱
- رشته‌های دریافتی از سرور در همه فهرست‌ها، جزئیات و صفحات فعالیت پیش از ورود به HTML ایمن‌سازی می‌شوند.
- صفحه WebView فقط منابع بسته‌بندی‌شده و درخواست‌های HTTPS به دامنه Supabase را با CSP می‌پذیرد.
- پاسخ‌های قدیمی مربوط به یک حساب دیگر، دیگر نباید جایگزین داده حساب فعلی شوند.
- وضعیت ثبت‌نام باز/بسته، ظرفیت و نبود بلیت معتبر در رابط جداگانه برچسب‌گذاری می‌شود.
- آزمون `node tests/online-ui-smoke.cjs` شامل داده‌های ساختگی خصمانه است؛ آزمون مرورگر واقعی و سرور مستقل همچنان لازم‌اند.
