# مسیر Release و حفظ داده — کانون‌ها ۰.۹.۱
تاریخ: ۲۰۲۶-۱۱-۰۸

## هدف این مرحله
خروجی `assembleRelease` با همان `applicationId=ir.kanonha.app` و افزایش
`versionCode` از ۱۵ به ۱۶ ساخته شود. امضای انتشار از فایل خارج از مخزن و
متغیرهای محیطی دریافت می‌شود؛ کلید خصوصی و گذرواژه هرگز نباید در GitHub قرار گیرند.

## تفاوت داده و امضا
- اطلاعات دانشجو/کانون/رویدادهای ثبت‌شده در Supabase اختصاصی ذخیره می‌شوند؛
  نصب نسخه جدید اپ نباید آنها را حذف کند. صحت این موضوع نیاز به آزمون بازیابی با حساب واقعی دارد.
- نشست ورود موقت در حافظه فرانت‌اند است و با بستن برنامه از دست می‌رود؛
  ورود مجدد ممکن است لازم شود، ولی **نشست با داده ثبت‌شده یکسان نیست**.
- فایل‌های لوکال نسخه‌های نمایشی در Android WebView/localStorage نگهداری می‌شوند.
  `android:allowBackup=false` فعال است؛ حذف برنامه داده‌های محلی را حذف می‌کند.
- **تغییر امضای Debug به Release با نصب روی نسخه فعلی سازگار نیست.**
  اگر قبلاً APK آزمایشی نصب کرده‌اید، آن را قبل از بررسی داده‌ها حذف نکنید.
  انتشار اولیه Release ممکن است نیازمند حذف نسخه Debug باشد و در نتیجه داده محلی از بین برود.
- از اولین نصب Release امضاشده با کلید ثابت به بعد، نسخه‌های جدید باید همان
  `applicationId`، همان گواهی امضا و `versionCode` بزرگ‌تر داشته باشند.

## ساخت Release
```bash
gradle :app:assembleRelease --no-daemon
# Without signing credentials it creates app-release-unsigned.apk
```
برای ساخت امضاشده در محیط مجاز، چهار متغیر زیر را تعریف کنید (بدون ثبت در Git):
```text
KANONHA_SIGNING_STORE=/private/path/kanonha-release.p12
KANONHA_SIGNING_STORE_PASSWORD=(secure secret)
KANONHA_SIGNING_ALIAS=kanonha-release
KANONHA_SIGNING_KEY_PASSWORD=(secure secret)
```
سپس `gradle :app:assembleRelease` را اجرا کنید. روی خروجی امضاشده آزمون
`apksigner verify --verbose --print-certs ...`، شناسه بسته و نصب ارتقایی انجام شود.

## مدیریت و بازیابی کلید
- کلید امضای اصلی پروژه مستقل کانون‌ها را رمزگذاری و در دو محل امن پشتیبان بگیرید.
- بدون کلید امضای قبلی، به‌روزرسانی بدون حذف برای توزیع مستقیم APK ممکن نیست.
- کلید نباید به مخزن عمومی، فایل `config.js`، کد اندروید، یا artifact عمومی CI وارد شود.
- اگر انتشار از Play Store انجام شود، قواعد Play App Signing جداگانه بررسی شود.

## معیارهای پذیرش
۱. Build Release موفق، بدون دیباگ، با `versionCode=16`.
۲. امضای APK از یک کلید ثابت پروژه و تأیید رسمی APK Signing Schemes.
۳. مقایسه اثر انگشت گواهی در نسخه‌های متوالی.
۴. نصب ارتقایی روی نسخه‌ای با **همان امضا**، بدون پاک شدن وضعیت کاربر.
۵. ورود مجدد به همان حساب و مشاهده داده سرور؛ آمار اصلی بدون افت/دستکاری.
۶. بررسی حداقل دو گوشی واقعی و بازنشانی نشست.

**تا اجرای کامل بندهای ۲ تا ۶، نسخه «آماده انتشار عمومی/تجاری» نیست.**
